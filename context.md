# PC Rotation Manager Pro — Application Context

Comprehensive overview of architecture, file structure, state management, APIs, desktop GUI, and persistence mechanisms.

---

## 1. Overview & Purpose
**PC Rotation Manager Pro** is a Windows desktop utility and local server designed to manage shared computer playtime and breaks between two players (**Joe** / Player 1 and **Marco** / Player 2).

Key responsibilities:
- Track active player countdown timer and stopwatch modes.
- Break system with break tokens, mutual agreements, and player-authenticated unfair breaks.
- Full desktop GUI (PyQt6) with system tray integration and dark theme.
- Persistent time alert system configured in `HH:mm:ss` format with selectable alarm sounds.
- Local FastAPI HTTP server with web-based mobile dashboard.
- Optional Discord Bot integration for remote status checks and player controls.
- Single-instance enforcement via `QSharedMemory` and local socket communication.

## 3. Data Persistence & Paths

### 1. Shared System State & Config (`C:\PCRotationManagerPro\`)
- **`state.json`**: Current active player, countdown times (`player1_time`, `player2_time` in minutes), break status, stopwatch minutes, break tokens.
- **`config.json`**: Server host/port, player secret codes (`p1_secret_code`, `p2_secret_code`), admin tokens, Discord bot configuration.
- **`logs/`**: Dated activity logs generated by `backend/logger.py`.

### 2. User & Alert Settings (`%LOCALAPPDATA%\PCRotationManagerPro\`)
- **`settings.json`**:
  ```json
  {
    "time_alert_enabled": true,
    "time_alerts": [3600, 1800, 900],
    "time_alert_toast_enabled": true,
    "time_up_toast_enabled": true,
    "alarm_sound_id": "time_up",
    "custom_alarm_sounds": [
      {
        "id": "custom:C:\\Users\\<you>\\Music\\alert.mp3",
        "name": "alert",
        "path": "C:\\Users\\<you>\\Music\\alert.mp3"
      }
    ]
  }
  ```
  - Saved atomically via `backend/settings.py` (`SettingsManager`).
  - Built-in sound IDs: `time_up` (`assets/alarm.wav`) and `chime` (`assets/chime.wav`).
  - Custom alarm sounds can reference `.wav`, `.mp3`, or `.ogg` files.

## 4. Core Architecture & Modules

### `backend/state_manager.py`
Central thread-safe state store (`threading.RLock`) managing:
- Background tick loop (`_tick_loop`) running every 1.0 second.
- Countdown logic (`_apply_elapsed`) tracking remaining times.
- Multi-alert threshold monitoring: Triggers the selected alarm sound when timer crosses configured seconds (`time_alerts`) unless already fired for that player's rotation.
- Break token management and fair/unfair break authorization using hashed or verified secret codes.
- Observer callbacks: `on_tick`, `on_alarm`, `on_time_alert`, `on_status_changed`.

### `backend/settings.py`
- `UserSettings` dataclass for alert toggles, multiple threshold lists (stored in integer seconds), selected alarm sound, and custom alarm sound references.
- `seconds_to_hhmmss` and `hhmmss_to_seconds` formatting helpers.
- Handles atomic write/replace to prevent corruption.

### `ui/main_window.py`
- PyQt6 dark UI (`#121212` background, `#2b2b2b` cards, `#4caf50` green accents).
- Seamless dark menu bar: **File** -> **Settings...** (`Ctrl+,`), **About** (`F1`), **Quit** (`Ctrl+Q`).
- Alarm banner with prominent **Dismiss Alarm** action.
- Alarm callbacks are routed through Qt signals so timer-thread triggers can safely start sound and update UI.
- Windows System Tray (`QSystemTrayIcon`) supporting minimize-to-tray and auto-restore on alarm trigger.

### `ui/settings_dialog.py`
- Configuration modal for alert thresholds (`QTimeEdit` with `HH:mm:ss` format).
- Add, Remove, and Clear alert thresholds with quick presets (`+15m`, `+30m`, `+45m`, `+1 hr`, `+1h 30m`).
- Alarm sound picker with built-in **Time's up** and **Chime** choices plus custom `.wav`, `.mp3`, and `.ogg` files.
- Custom sounds appear in the same list with a small trash button for removal.
- Interactive selected-sound test button.

### `ui/alarm.py`
- `AlarmPlayer` plays the selected alarm sound until `stop()` or UI dismiss.
- Automatically generates dual-tone melodic chime WAV (`assets/chime.wav`: 659.25Hz -> 880Hz) on startup.
- Built-in **Time's up** sound uses `assets/alarm.wav`; **Chime** uses `assets/chime.wav`.
- WAV files loop instantly via `winsound.PlaySound(..., SND_LOOP)`.
- MP3/OGG files loop via `PyQt6.QtMultimedia.QMediaPlayer`, with an audible fallback loop if media playback fails.

### `backend/server.py` & `web/dashboard.html`
- FastAPI REST service running via `uvicorn` on a separate background thread (default `0.0.0.0:8000`).
- REST Endpoints:
  - `GET /status` — returns current state snapshot.
  - `GET /logs` — recent log lines.
  - `POST /switch_player` — switches active player (admin authenticated).
  - `POST /start_break` — starts mutual break.
  - `POST /start_unfair_break` — requires both player codes.
  - `POST /player_break` / `POST /stop_player_break` — token-based breaks with secret code.
- Serves responsive web dashboard (`/`) for mobile browser control over local Wi-Fi.

### `backend/discord_bot.py`
- Runs `discord.Client` / `app_commands` slash bot if configured with bot token.
- Slash commands: `/status`, `/switch`, `/break`, `/endbreak`, `/logs`.

## 5. Native Android Mobile App

### Purpose
The `mobile port/PCRotationManagerPro/` project is a native Android companion app for checking and controlling the local PC rotation server from a phone on the same network.

Primary responsibilities:
- Display live player timers, active player, break token counts, finish estimates, break status, stopwatch state, and active alarm state.
- Start and stop active-player breaks through secret-code-protected API calls.
- Poll the PC FastAPI server in the foreground for live status and notifications.
- Notify the phone when a PC alarm becomes active or when the active player switches.

### Build & Platform
- Android Gradle project using Kotlin and Jetpack Compose Material 3.
- Namespace/application ID: `com.marco.pcrotationmanagerpro`.
- `compileSdk = 37`, `targetSdk = 36`, `minSdk = 30`.
- Main build files:
  - `mobile port/PCRotationManagerPro/settings.gradle.kts`
  - `mobile port/PCRotationManagerPro/build.gradle.kts`
  - `mobile port/PCRotationManagerPro/app/build.gradle.kts`
  - `mobile port/PCRotationManagerPro/gradle/libs.versions.toml`
- Important dependencies: AndroidX Core KTX, Lifecycle Runtime KTX, Activity Compose, Compose BOM, Compose UI, Compose Material 3.

### Android Manifest
`mobile port/PCRotationManagerPro/app/src/main/AndroidManifest.xml` declares:
- `INTERNET` and `ACCESS_NETWORK_STATE` for local server communication.
- `POST_NOTIFICATIONS` for Android 13+ notification permission.
- `FOREGROUND_SERVICE` and `FOREGROUND_SERVICE_SPECIAL_USE` for persistent background polling.
- `android:usesCleartextTraffic="true"` so the app can call the local `http://` FastAPI server.
- Launcher activity: `.MainActivity`.
- Foreground service: `.service.PollingService` with `foregroundServiceType="specialUse"`.

### API Client
`api/ApiService.kt` is a lightweight coroutine-based HTTP client built on `HttpURLConnection`.

Default server:
- `http://<YOUR_IP>:6969`

Supported calls:
- `GET /status` -> parsed into `StatusResponse`.
- `POST /start_player_break` with JSON `{ "reason": "...", "secret_code": "..." }`.
- `POST /stop_player_break` with JSON `{ "secret_code": "..." }`.
- `GET /health` -> parsed into `HealthResponse`.

Request behavior:
- Network work runs on `Dispatchers.IO`.
- Status calls use 5-second connect/read timeouts.
- Health calls use 3-second connect/read timeouts.
- The app currently parses JSON manually with `org.json.JSONObject`; it does not use Retrofit.

### Data Models
`api/Models.kt` mirrors the desktop server status shape:
- `StatusResponse`: player times, active player, stopwatch state, break tokens, break status/reason/player, alarm state, depleted flags, unfair-break flag.
- `BreakResponse`: `ok` and `message`.
- `HealthResponse`: `ok` and `url`.

### Main Activity
`MainActivity.kt`:
- Initializes `ApiService`.
- Requests `POST_NOTIFICATIONS` on Android 13+.
- Starts `PollingService` after permission is granted, and again from `onStart()`.
- Hosts the Compose UI via `PCRotationManagerProTheme`.
- Runs UI-only polling every 3 seconds with `LaunchedEffect`.
- Updates connection text between `Connecting...`, `Online`, `Offline`, and `Cannot reach PC server`.
- Starts/stops player breaks through `ApiService`, showing Android `Toast` feedback for success/failure.
- Shows a toast when the mobile user taps dismiss alarm, because alarms must be dismissed from the PC app.

### Compose UI
`ui/screens/MainScreen.kt`:
- Dark, scrollable dashboard matching the desktop color palette.
- Shows stacked `PlayerCard` components for Player 1 and Player 2.
- Highlights the active player unless the system is on break.
- Shows timer text, finish estimate, break tokens, active-player status, break badges, stopwatch badge, and alarm badge.
- Shows an alarm banner with a Dismiss button that delegates to the PC-only dismiss toast behavior.
- Shows either **Start Break** or **Stop Break** depending on `on_break`.
- Uses `BreakDialog.kt` and `StopBreakDialog` for secret-code-protected break actions.

`ui/components/PlayerCard.kt`:
- Renders player title, countdown, finish estimate, break token text, and progress bar.
- Uses 2 maximum break tokens by default.
- Changes border/background for active player and timer color when low/depleted.

`ui/theme/`:
- `Color.kt` defines desktop-matching colors (`#121212`, player green/blue, orange, red, yellow).
- `Theme.kt` sets a dark Material 3 color scheme and dark status bar.

### Background Polling & Mobile Notifications
`service/PollingService.kt`:
- Android `Service` running as a foreground service with an ongoing low-priority notification.
- Polls `/status` every 3 seconds via `ApiService`.
- Updates foreground notification text with current P1/P2 time and active player.
- Shows "PC server offline — retrying..." when polling fails.
- Tracks previous `alarm_active` and active-player values to avoid duplicate notifications.
- Sends a time-up notification when `alarm_active` transitions from false to true.
- Cancels the time-up notification when `alarm_active` clears.
- Sends a player-switch notification when active player changes.

`notifications/NotificationHelper.kt`:
- Creates a high-importance `Timer Alarms` notification channel.
- Sends **TIME UP!** notifications with vibration.
- Sends **Player Switch!** notifications with vibration and the default notification sound.
- Silently ignores notification calls if runtime permission is missing.

### Mobile Limitations / Current Behavior
- Server URL is hardcoded in `ApiService` to `http://<YOUR_IP>:6969`; `updateBaseUrl()` is currently a stub.
- Mobile app can start and stop player breaks, but cannot switch players, dismiss PC alarms, edit settings, or manage custom PC alarm sounds.
- Mobile notifications observe the server's `alarm_active` state; the phone does not play the PC-selected custom alarm sound.
- Mobile app depends on the phone and PC being on the same reachable LAN and the desktop FastAPI server being running.

## 6. Security & Single-Instance Mechanics
- **Single Instance**: `main.py` creates a named `QSharedMemory("PCRotationManagerPro-Instance")`. If already active, it sends `b"show"` over `QLocalSocket` to `QLocalServer` to focus the existing instance.
- **Admin Access**: Protected via `Bearer` token in `config.json`.
- **Secret Codes**: Each player has an individual secret code in `config.json` for authorized token spending and unfair break triggers.
